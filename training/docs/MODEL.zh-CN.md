## 几何与动力学

| 项目 | 数值/实现 | 证据或假设 |
| --- | --- | --- |
| 整机质量 | 0.5783kg | 用户确认已含电池和CM5 |
| CM5完整总成 | 0.0628kg | 用户确认包括外壳、风扇、散热等；单独固定刚体 |
| 电池、单轮、单腿舵机 | 68.9g、132.9g、21.1g | 照片读数及用户报告；另一侧按等重 |
| 胎径、胎宽 | 61.6mm、15.7mm | 所给 STEP 包围盒 |
| 双轮中心距 | 86.6mm | 所给 STEP |
| 坐标 | x 前、y 左、z 上 | CAD 的 -X、+Z、+Y，右手系 |
| 底盘 | 完整 3D free joint | 没有固定俯仰、横滚或平面运动约束 |
| 腿 | 两个等效伸缩关节 | 保留固件 45–81mm 运动学和调平；未建立完整四连杆动力学 |
| 腿位置环 | kp=1200N/m、kv=5N·s/m，限力15N | 未辨识假设 |
| 刚体名义分配 | 机身198.018g、CM5 62.8g、腿及定子98.936g×2、转子及胎59.805g×2 | 实测总质量约束；定子/转子名义55%/45%，连杆分配依CAD代理 |
| 转动惯量、重心 | CAD中央惯量按质量加权、平行轴合并完整张量 | CM5名义重心[36.493,-0.190,-8.250]mm；内部材料代理未经物理重心测量验证 |
| 轮驱 | 等效比例速度环，扭矩饱和 .13N·m | 官方给出额定扭矩与400RPM；命令映射、速度环增益/带宽未测量 |

轮驱等效公式为 `torque = clip(torque_limit * (u - back_emf * omega), ±torque_limit)`，
后接一阶动态。名义 `back_emf=1/41.89`，等效目标角速度 `41.89*u rad/s`。
它也可看作低增益比例速度环；**协议里的整数不是已标定的扭矩或电流**。
FOC 真实速度环可能有积分及不同的增益/饱和。额定扭矩也不等于已知堵转扭矩。
最终上机需要辨识命令、轮速、延迟和饱和的实际关系。

腿关节有内部重力前馈，以避免假设的位置环静差改变整机高度。
没有给机身加平衡弹簧、抗倾倒力或固定姿态力矩。测试验证：零轮动作会倒地；
无扰动时机身外加力为零。离地/接触/俯仰/横滚均由 MuJoCo 求解。

STEP 网格只供显示，经过三角面简化；有少量原始 STEP 面无法三角化。
显示时四连杆随等效腿关节平移，不能用于机械干涉或完整连杆动力学验收。
训练使用小型碰撞几何。自动检查确保 CAD 显示模型的质量、惯量、关节及驱动参数完全一致。

## 固件一致性

`native/firmware_bridge.cpp` 编译并运行实际的 `MotionController`、IMU 滤波、
腿目标生成和 `ActuatorDecoder`，不在 Python 里重写这些算法。
反馈通过真实帧解码，包含整数速度量化、ID21 方向、编码器回绕和原始轮速滤波。
原 PID 保留滤波轮速；策略输入使用最近一次返回的轮速，以减少输入滞后。
v4 共18个观测，还包含限速取整后的实际轮命令、控制间隔和转向积分状态，完整顺序见固件 `firmware/docs/RL_POLICY.zh-CN.md`。

物理传感器经安装坐标变换、量化、噪声后才进入原始 IMU 字节解码。
不能把固件的 pitch 角速度符号直接当作物理 Euler 导数。
执行器按 `{11,21,11,21,11,21,11,21,12,22}` 顺序采样，包含反馈等待和命令保持。
推理间隔受控制循环约束：名义控制6ms、策略12ms；随机控制4/6/8ms，对应策略12/12/16ms。
首次动作限80单位，之后按20000单位/秒限速，双轮最终限幅±1023。

固件原来的轮速与里程使用55mm轮径。策略单独乘 `61.6/55`，不改原 PID 的换算。
这里修正的是 CAD 标称半径；实际滚动半径仍待标定。

`native/policy_bridge.cpp` 让相同的 MCU C++ 推理与 Controller 在 MuJoCo 中闭环运行。
正式模型附带转向积分校正，用角速度误差按实际控制间隔积分，作用于两轮相同的原生方向。
学习网络仍负责共同轮驱动和平衡。积分增益/限幅随模型导出并参与模型摘要，停机/arm时清零。
它不是机身外力，全部控制仍经过轮电机、变化率与协议限幅。
模拟微秒时间推进，与 macOS 调度时间分开，避免把桌面进程抢占当作 MCU 超时。
因此仿真不能证明 ESP32 上的2ms推理期限；需在下位机 shadow 模式实测。

## 随机化与压力测试

以下是 `measured` 配置的 `domain=1` 范围；每次reset先分配零部件质量，再重算各刚体重心和完整惯量，保持总质量约束：

| 参数 | 范围 |
| --- | --- |
| 总质量倍率 | .975–1.025 |
| CM5/电池/单轮及舵机质量 | ±0.8% / ±1% / ±2%；余量分给未称重结构 |
| CM5子件质量分布 | 各子件名义代理±40%，保持完整总成质量约束 |
| 定子质量占单轮总成 | 35–75%；名义55% |
| 惯量额外倍率 | .8–1.2，另含质量分配与平行轴变化 |
| 部件内部重心扰动 | CM5子件x±1mm、y/z±3mm；电池±2mm；结构小件±1.5mm |
| 地面摩擦 | .55–1.15 |
| 轮驱限矩倍率 | .75–1.25 |
| 等效空载转速 | 280–520RPM |
| 轮驱一阶时间常数 | 8–24ms |
| 轮命令额外延迟 | 0–8ms |
| 控制、反馈时隙 | 4/6/8ms、2/4/6ms |
| 编码器比例 | .96–1.04 |
| 地面倾斜 | ±2.0° |
| 陀螺仪偏置、噪声 | ±.2°/s、σ=.08°/s |
| 加速度偏置、噪声 | ±.025m/s²、σ=.015m/s² |
| 外力扰动 | .1–.7N，80ms，间隔1–3s |

训练还会增加 `lag`、`fast` 和 `corner` 边界样本。
`corner` 在实测质量配置下强化较大扭矩/延迟及快、慢电机响应；质量分配仍按同一校准范围采样。旧legacy配置额外使用重心/惯量角点。`domain=.5` 将连续参数变化减半，
控制/反馈时隙仍覆盖上述离散集合，摩擦范围也保持不变。
初始俯仰±.06rad、横滚±.012rad、随机航向；训练前进±.16m/s、转向±.6rad/s及不同高度。

早期试验的反电势随机化等效空载转速达250–2000RPM，超过官方400RPM规格的合理扰动。
旧报告保留，现命名为 `legacy_extreme` 压力工况；它不与正常范围合并计算通过率。
仍可以 `evaluate.py ... --profile legacy_extreme` 明确重跑。

以上连续参数与反馈假设尚无实机辨识支撑。随机化通过说明策略能适应这些**模型内变化**，
不能证明真实硬件恰好落在范围内。

## 基线的边界

独立 LQR 用于 actor 初始拟合，随后运行真实 MuJoCo PPO 训练。
转向前馈通过监督投影拟合进相同的输出层，再做 PPO 优化；这一校准保留共同轮扭矩，
训练方法在模型来源中明确记录。它不是纯随机从零训练。
不把 LQR 输出伪装成强化学习训练成果；最终产物来自保存的学习后 checkpoint。
恢复的原 PID 在这套等效轮驱模型上没有稳定通过，因此不能用它与神经网络的仿真差异
宣称超越原厂控制。该现象也提示轮驱模型与实机响应仍需核对。

本项目完成的是模型内训练、独立评估、导出和本地交叉编译。没有刷写、驱动实体机器人，
也没有把仿真分数当成实机闭环验收。

### 2026-10-21 实测质量修正

独立物理配置 `measured` 使用578.3g整机（已含电池）、62.8g完整CM5总成、132.9g单轮、68.9g电池和21.1g单腿舵机。质量分布、完整惯量及不确定性见 `models/mass_audit/REPORT.md`。`RiderEnv(physics="measured")`、`train.py --physics measured` 和 `evaluate.py --physics measured` 使用此配置；训练记录包含物理模型哈希。CM5的CAD加权重心是估算值，尚未经物理重心测量验证。

原 `legacy` 质量模型仍为机身420g、移动腿25g×2、整轮45g×2；总质量倍率.82–1.18、惯量.75–1.25、基座重心偏移±3/1/8mm。它只用于旧报告复现，不是这台设备的实测质量配置。

新版转向积分增益/限幅为0.08/0.08，与导出模型、训练配置和原生C++一致；只产生轮端动作，不对机身直接施力。


### 2026-10-21 contract 5：双轮 + 双舵机残差

训练环境升级为四维动作：两轮直接命令，以及两条腿的伸缩残差（每维 ±5mm，归一化后经 10/s 限速）。
腿部基准高度、几何和侧倾调平仍由与固件同源的 `LegPositionController` 生成；仿真改为直接编译该控制器，
并新增舵机一阶跟踪滞后（约 8–80ms，随domain变化）、连杆回差、轮速反馈噪声、更大的命令/反馈延迟随机化。
奖励增加了车身角速度阻尼项，动作变化惩罚覆盖到腿部通道。

观测仍为 18 维；`contract=5`、`architecture=[18,32,32,4]`、`action_space=wheels_legs`。
旧 `contract 4` 的 2 输出 checkpoint 可通过 `tools/expand_policy.py` 做代数转换后热启动：
它会先去掉旧 common-turn 动作层的坐标变换，再把两个新腿部输出置零。

新策略在原生 C++ 下的推理、逐 tick 限速/限幅和腿部目标换算由 `verify_export.py` 与
`rider/rider2-firmware` 的主机测试共同核对。仿真通过不等于实机通过，实机仍需观察抖动与恢复表现。
